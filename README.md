# design-baseline

새 앱과 게임을 만들 때 쓰는 기준 문서입니다.

- [`DESIGN.md`](DESIGN.md): 앱·웹 UI/UX 기준(v1.5.0: 내용 먼저 — 첫 화면은 내용, 안내는 그 아래, 꾸밈 딱지 없음, 옅은 강조. 읽기·편집·보드·갤러리 같은 내용 중심 화면은 종이 하나·떠 있는 도구 판. 넓은 화면은 폭을 다 쓰고 읽는 폭만 제한, 기본 메뉴는 왼쪽에 떠 있는 얇은 레일. 주 단추 마감은 §0에서 앱마다 고름)
- [`GAME_DESIGN.md`](GAME_DESIGN.md): 게임 정체성 고정, 그레이박스 재미 검증, 시각·HUD·연출 흐름·실제 판 안에서 배우는 튜토리얼·조작감·보상·학습 게임·저사양 성능·에셋 출처·접근성·런타임 기준, 자동 검증 + 사람 플레이테스트
- [EVAL.md](EVAL.md) — 판정·검색/추천·추출·생성처럼 출력이 그럴듯하게 틀릴 수 있는 기능에서 평가를 언제 권하고 어떻게 짜는지 정한 기준

## 쓰는 법

1. UI·게임을 만들 때 새 저장소 루트에 해당 디자인 파일을 복사합니다. 게임 안의 메뉴·설정 화면처럼 둘 다 해당하면 둘 다 복사합니다.
2. `DESIGN.md`는 `§0 Project Overrides`만 고칩니다. `GAME_DESIGN.md`는 기능 코드를 쓰기 전에 `§0 Game Identity & Creative Lock`부터 채웁니다.
3. 두 디자인 문서의 나머지 절은 그대로 따릅니다.
4. 기능의 결과 품질을 판단할 때는 `EVAL.md`를 참고해 제품에 맞는 표본과 채택 기준을 정합니다.
